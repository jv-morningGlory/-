# 观察者模式(Observer Pattern)

## 解决什么问题

一个对象状态变化时,要通知一堆其他对象,又不想和它们强耦合。比如订单状态一变,要发短信、发邮件、更新库存、推送消息——如果直接在订单类里调这些,增减通知方就得改订单类。

观察者模式:被观察者(**主题**)维护一个观察者列表,状态变化时遍历通知,**主题不需要知道观察者是谁、有几个**。

---

## Java 代码示例

订单状态变更,自动触发短信和邮件通知。

```java
import java.util.ArrayList;
import java.util.List;

// ========== 观察者接口 ==========

interface Observer {
    void update(String orderStatus);
}

// ========== 主题(被观察者)==========

class OrderSubject {
    private final List<Observer> observers = new ArrayList<>();
    private String status;

    public void attach(Observer o) { observers.add(o); }
    public void detach(Observer o) { observers.remove(o); }

    public void setStatus(String status) {
        this.status = status;
        notifyAllObservers();
    }

    private void notifyAllObservers() {
        for (Observer o : observers) {
            o.update(status);
        }
    }
}

// ========== 具体观察者 ==========

class SmsNotifier implements Observer {
    public void update(String orderStatus) {
        System.out.println("发短信:订单已 " + orderStatus);
    }
}

class EmailNotifier implements Observer {
    public void update(String orderStatus) {
        System.out.println("发邮件:订单已 " + orderStatus);
    }
}

// ========== 客户端 ==========

public class Client {
    public static void main(String[] args) {
        OrderSubject order = new OrderSubject();
        order.attach(new SmsNotifier());
        order.attach(new EmailNotifier());
        order.setStatus("已发货");   // 自动触发短信 + 邮件
    }
}
```

> 主题只依赖 `Observer` 接口,新增通知方式(比如加个日志)只需新建一个观察者类,主题代码不用动。
