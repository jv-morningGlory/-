# 策略模式(Strategy Pattern)

## 解决什么问题

同一件事有多种做法,需要根据条件切换。比如支付可选微信/支付宝/银行卡,促销折扣有满减/打折/无。如果用 `if-else` 区分,代码臃肿,新增一种就得改判断逻辑,违反开闭原则。

策略模式:把每种做法封装成独立的策略类,通过统一接口替换,**消除一长串条件判断**。

---

## Java 代码示例

支付方式可替换,无需 if-else。

```java
// ========== 策略接口 ==========

interface PaymentStrategy {
    void pay(int amount);
}

// ========== 具体策略 ==========

class WeChatPay implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("微信支付 " + amount + " 元");
    }
}

class AliPay implements PaymentStrategy {
    public void pay(int amount) {
        System.out.println("支付宝支付 " + amount + " 元");
    }
}

// ========== 上下文:持有策略,可替换 ==========

class PaymentContext {
    private PaymentStrategy strategy;

    public PaymentContext(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void checkout(int amount) {
        strategy.pay(amount);
    }
}

// ========== 客户端 ==========

public class Client {
    public static void main(String[] args) {
        PaymentContext ctx = new PaymentContext(new WeChatPay());
        ctx.checkout(100);              // 微信支付 100 元

        ctx.setStrategy(new AliPay());
        ctx.checkout(200);              // 支付宝支付 200 元
    }
}
```

> 上下文只依赖 `PaymentStrategy` 接口,新增支付方式只需加一个实现类,调用方和判断逻辑都不用改。
