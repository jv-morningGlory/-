# 工厂模式(Factory Pattern)

## 解决什么问题


工厂模式:把 `new` 的活交给工厂,**调用方只说"我要什么",不关心怎么造**。对象创建与使用分离。

---

## 三种形态

工厂模式是一族,按复杂度分三种:

| 形态 | 特点 | 何时用 |
|------|------|--------|
| 简单工厂 | 一个工厂方法 + 参数判断返回不同产品 | 产品少、变化不频繁 |
| 工厂方法 | 每种产品配一个工厂,符合开闭原则 | 产品会持续扩展 |
| 抽象工厂 | 一次造一个产品族,保证风格统一 | 多维度关联产品 |

---

## Java 代码示例

### 1. 简单工厂(最常用,非 GoF)

```java
// ========== 抽象产品 ==========

interface Payment {
    void pay(int amount);
}

// ========== 具体产品 ==========

class AliPay implements Payment {
    public void pay(int amount) {
        System.out.println("支付宝支付 " + amount + " 元");
    }
}

class WeChatPay implements Payment {
    public void pay(int amount) {
        System.out.println("微信支付 " + amount + " 元");
    }
}

// ========== 工厂:根据参数造产品 ==========

class PaymentFactory {
    public static Payment create(String type) {
        if ("ali".equals(type)) return new AliPay();
        if ("wechat".equals(type)) return new WeChatPay();
        throw new IllegalArgumentException("未知支付类型");
    }
}

// ========== 客户端 ==========

public class Client {
    public static void main(String[] args) {
        Payment p = PaymentFactory.create("ali");  // 不 new,问工厂要
        p.pay(100);
    }
}
```

> 缺点:每加一种新产品都要改工厂的 create 方法,违反开闭原则。

### 2. 工厂方法(GoF 23 种)

把工厂抽象化,每种产品配一个工厂:

```java
// ========== 抽象工厂 ==========

interface PaymentFactory {
    Payment create();
}

// ========== 具体工厂:一个工厂造一种产品 ==========

class AliPayFactory implements PaymentFactory {
    public Payment create() { return new AliPay(); }
}

class WeChatPayFactory implements PaymentFactory {
    public Payment create() { return new WeChatPay(); }
}
```

> 加新产品只新增一个工厂类,不改老代码,符合开闭原则。

---

## 适用场景

- 创建对象逻辑复杂:要读配置、初始化多步、依赖外部资源
- 同一接口多个实现,运行时才决定用哪个
- 想集中管理对象创建,方便后续扩展

> 反之,对象只有一种、`new` 一下就行,别用,纯属过度设计。

---

## SpringBoot 为什么大量用工厂

Spring 的 IoC 容器本身就是一个超级工厂。

### 1. BeanFactory / ApplicationContext

Spring 顶层工厂接口。你把类交给 Spring(`@Component` / `@Bean`),Spring 负责造对象、注入依赖、管理生命周期:

```java
UserService userService = context.getBean(UserService.class);  // 不 new,问工厂要
```

### 2. FactoryBean —— 用户自定义工厂

当 Bean 不能直接 new(复杂构造、代理、第三方对象),实现 `FactoryBean` 自己写:

```java
public class MyFactoryBean implements FactoryBean<Connection> {
    @Override
    public Connection getObject() {
        return createSqliteConnection();  // 复杂创建逻辑
    }
    @Override
    public Class<?> getObjectType() { return Connection.class; }
}
```

典型应用:MyBatis 的 `SqlSessionFactoryBean`、Spring AOP 代理对象、Dubbo 的 `ReferenceBean`。

### 3. 自动配置也是工厂

`spring.factories`(旧)/ `AutoConfiguration.imports`(新),底层就是工厂机制加载自动配置类。

### 4. 这样设计的好处

- **解耦**:业务只面向接口,不关心谁造的
- **统一生命周期**:初始化、销毁、作用域(单例/原型)由工厂统一管
- **方便扩展**:加新实现只注册 Bean,不改调用方
- **支撑 AOP**:造 Bean 时统一包一层代理,实现事务/日志切面

> 一句话:Spring 把"对象创建和管理"用工厂模式做到极致,这就是 IoC(控制反转)的本质。
