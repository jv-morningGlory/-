**笔记：**

#### 什么是 Embedding

**Embedding** = 把文本映射到高维空间中的一个向量（一串浮点数），使得语义相近的文本在空间中方向接近。

> 向量 = 方向 + 长度。在 NLP 中，**方向代表语义**，长度通常代表文本长度或出现频率，所以比相似度时只看方向（余弦相似度），不看距离（欧氏距离）。

| 概念 | 通俗理解 |
|------|---------|
| Embedding 模型 | 一个训练好的函数，输入文本，输出固定维度的向量（如 1536 维） |
| 词嵌入（Word Embedding） | 把单个词转成向量，如 Word2Vec、GloVe |
| 句/文档嵌入 | 把整句话或整段文本转成向量，如 OpenAI text-embedding-3、BGE |

#### 余弦相似度 — 怎么算两个字/文本有多像

**核心直觉：** 两个向量在空间中夹角越小 → 方向越一致 → 语义越接近。

**公式：**

```
cos(θ) = (A·B) / (|A| × |B|)
       = (x₁x₂ + y₁y₂) / (√(x₁²+y₁²) × √(x₂²+y₂²))
```

- `A·B` = 向量点积（对应维度相乘再求和）
- `|A|` = 向量的模（长度）
- 结果范围 `[-1, 1]`：1 = 同向（语义相同），0 = 正交（无关），-1 = 反向（语义相反）

> 图解参考 → [余弦相似度图解](../余弦相似度图解.html)

**为什么不用欧氏距离？** 两个文本可能长度差很多（向量长度不同），但说的是同一件事（方向相同）。欧氏距离会被长度误导，余弦相似度只看方向。

#### 向量检索原理 — 怎么从百万向量中快速找到最相似的

**核心问题：** 给定一个查询向量，在海量向量中找 Top-K 最相似的 → 暴力遍历太慢（O(n)）。

**解决思路：** ANN（近似最近邻），牺牲一点精度换速度（O(log n)）。

| 算法/方案 | 核心思想 | 特点 |
|-----------|---------|------|
| KNN（精确检索） | 计算查询向量与所有向量的余弦相似度，排序取 Top-K | 精度 100%，百万级就扛不住 |
| LSH（局部敏感哈希） | 哈希函数让相邻向量更可能落在同一个桶里 | 最早一代 ANN |
| HNSW（分层可导航小世界图） | 构建多层图结构，每层跳跃搜索逼近目标 | 当前主流，查询快、精度高 |
| IVF（倒排索引） | 先聚类成 N 个簇，查询时只搜最近几个簇 | 常与 PQ 量化组合使用 |

> **实际落地：** 不需要手写 ANN 算法。向量数据库（Milvus、PgVector、Qdrant）已经内置了，你只需要选索引类型（如 HNSW）和调参数。

#### Java 调 Embedding API — 实操要点

本质就是调一个 HTTP 接口，传文本、返回向量数组。

**一般流程：**

```
文本 → Embedding API → 拿到 float[] 向量 → 存向量数据库 / 计算相似度
```

**关键注意事项（踩坑经验）：**

1. **向量维度要一致** — 写入和查询必须用同一个 Embedding 模型，不同模型的维度不同（OpenAI 是 1536，BGE 是 768），混用直接报错
2. **同一文本不同模型结果不同** — 相似度阈值不能照搬，换了模型阈值要重新评估
3. **文本预处理** — 调用 API 前去掉无意义字符、截断超长文本（注意模型的 token 上限）
4. **Token 计费** — Embedding API 按 token 收费，和 LLM 一样，注意成本控制
5. **批量调用** — 大多数 API 支持一次传多条文本，比逐条调效率高很多

#### Function Calling — 让 LLM 从"说话"变成"动手"

**核心概念：** LLM 本身**不执行**任何代码，它只是输出"我想调哪个函数、参数是什么"，执行是你的代码做的事。

```
普通对话：  用户 → LLM → 回答文本
Function Calling：用户 → LLM → 返回 JSON（函数名 + 参数）→ 你的代码执行 → 结果回传 LLM → 最终回答
```

LLM 返回的 JSON 长这样（示意）：

```json
{
  "name": "get_weather",
  "arguments": {
    "city": "北京",
    "date": "明天"
  }
}
```
