## 分布式 ID 方案

### 三种方案对比

| 方案 | 有序性 | 唯一性 | 插入性能 | 分库分表友好 | 缺点 |
|------|--------|--------|----------|-------------|------|
| **自增 ID** | 有序 | 单库唯一 | 高 | 差 | 老数据导入可能重复；分库分表会冲突 |
| **UUID** | 无序 | 全局唯一 | 差 | 好 | 无序导致频繁页分裂，产生碎片，影响插入性能 |
| **雪花算法** | 有序 | 全局唯一 | 高 | 好 | 强依赖时间戳，时间回拨可能导致重复 |

### 雪花算法详解

Snowflake 生成的 ID 由以下部分组成（64 位）：

- 1 位符号位（0）
- 41 位时间戳（毫秒级，约可用 69 年）
- 10 位工作机器 ID（可部署 1024 个节点）
- 12 位序列号（同一毫秒内可生成 4096 个 ID）

> 时间回拨问题：雪花算法强依赖时间戳，出现时间回拨可能产生重复 ID。解决方案包括：回拨时拒绝生成、使用历史最大时间戳等。

### 结论

推荐使用雪花算法，兼顾有序性和唯一性。成熟的分布式 ID 工具：

- **Twitter Snowflake**：原始方案
- **美团 Leaf**：支持号段模式和雪花算法模式
- **百度 UIDGenerator**：基于雪花算法，Java 实现

## 分库分表

### 为什么要拆分？

InnoDB 数据页默认 16KB，单行数据过大会导致每页存储行数减少、B+ 树层数增加、查询性能下降。当数据量超过单节点承载能力时，需要拆分。

### 垂直拆分

将单行数据中的大字段或不同业务模块拆到不同的表/库中。

- **目的**：减小单行数据体积，提高数据页密度
- **局限**：缓解问题但无法根治，数据量持续增长仍需水平拆分

> 应在设计初期就考虑是否需要拆分，避免后期改造成本。

### 水平拆分

将一个表的数据按水平维度切割到多个表/库中。

### 分片算法

| 算法 | 原理 | 范围查询 | 数据均匀性 | 动态伸缩 | 推荐 |
|------|------|----------|-----------|----------|------|
| **哈希分片** | 对分片键取哈希，根据哈希值分配 | 不适合 | 均匀 | 不友好（新增节点需重新分布） | 不推荐 |
| **范围分片** | 按区间分配（如 ID 1~30W、30W~60W） | 适合 | 可能不均匀（热点问题） | 友好 | 视业务场景 |
| **映射表分片** | 独立表存储分片键与位置的映射 | 支持 | 取决于规则 | 灵活 | 不推荐（额外开销） |
| **一致性哈希** | 环形结构，顺时针分配到最近节点 | 一般 | 较均匀 | 友好（解决传统哈希伸缩问题） | **推荐** |

> 一般根据业务选择**范围分片**或**一致性哈希分片**。范围分片适合按时间/ID 有序的场景，一致性哈希适合随机读写场景。

## ShardingSphere 读写分离

### Maven 依赖

```xml
<dependency>
    <groupId>org.apache.shardingsphere</groupId>
    <artifactId>shardingsphere-jdbc-core</artifactId>
    <version>5.x.x</version>
</dependency>

<!-- 注意：引入 Druid 不能用 springboot starter，会自动注入空 datasource -->
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid</artifactId>
    <version>1.1.22</version>
</dependency>
```

### YAML 配置

```yaml
spring:
  shardingsphere:
    datasource:
      names: ds_master,ds_slave_0
      ds_master:
        type: com.alibaba.druid.pool.DruidDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        url: jdbc:mysql://127.0.0.1:3306/test_01?useUnicode=true&characterEncoding=utf-8&serverTimezone=UTC
        username: root
        password: your_password
      ds_slave_0:
        type: com.alibaba.druid.pool.DruidDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        url: jdbc:mysql://127.0.0.1:3307/test_01?useUnicode=true&characterEncoding=utf-8&serverTimezone=UTC
        username: root
        password: your_password
    props:
      sql-show: true

    rules:
      readwrite-splitting:
        load-balancers:
          roundRobin:
            type: ROUND_ROBIN
        data-sources:
          read_write_db:
            type: Static
            props:
              write-data-source-name: ds_master
              read-data-source-names: ds_slave_0
              transactional-read-query-strategy: PRIMARY
            load-balancer-name: roundRobin

mybatis:
  type-aliases-package: com.example.entity
  mapper-locations: classpath:mapper/*.xml
  configuration:
    map-underscore-to-camel-case: true
```

### 启动类配置

```java
@SpringBootApplication(scanBasePackages = "com.example.*")
@MapperScan("com.example.mapper")
@EnableTransactionManagement
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

### 关键配置说明

| 配置项 | 说明 |
|--------|------|
| `transactional-read-query-strategy: PRIMARY` | 事务中的读操作强制走主库，避免读到从库的延迟数据 |
| `@EnableTransactionManagement` | 开启事务管理 |
| Druid 不能用 `druid-spring-boot-starter` | Spring Boot 自动配置会注入空 DataSource，与 ShardingSphere 冲突 |

### 强制走主库

在查询方法上加 `@Transactional` 注解，配合 `transactional-read-query-strategy: PRIMARY`，事务内的读操作会走主库。

### 主库故障处理

主库挂掉是严重故障，应用无法执行写操作。推荐与 **HA（高可用）工具**结合：

```yaml
dataSources:
  ds_master:
    # 配置为 HA 工具提供的 VIP 或域名
    url: jdbc:mysql://mysql-vip.prod:3306/db?serverTimezone=UTC
  ds_slave_0:
    url: jdbc:mysql://mysql-slave0.prod:3306/db?serverTimezone=UTC
```

当 HA 工具完成主从切换后，应用通过 VIP 连接到新主库，ShardingSphere **无需修改配置和重启**。

## SpringBoot + MyBatis Plus + 多数据源

### Maven 依赖

```xml
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>8.0.22</version>
    <scope>runtime</scope>
</dependency>

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.4.3.4</version>
</dependency>

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot-starter</artifactId>
    <version>3.6.1</version>
</dependency>
```

### YAML 配置

```yaml
spring:
  datasource:
    dynamic:
      primary: master
      strict: false
      datasource:
        master:
          url: jdbc:mysql://127.0.0.1:3306/test_sql?useUnicode=true&characterEncoding=utf-8&serverTimezone=UTC
          username: root
          password: your_password
          driver-class-name: com.mysql.cj.jdbc.Driver
        test_sql2:
          url: jdbc:mysql://127.0.0.1:3306/test_sql2?useUnicode=true&characterEncoding=utf-8&serverTimezone=UTC
          username: root
          password: your_password
          driver-class-name: com.mysql.cj.jdbc.Driver

mybatis-plus:
  mapper-locations: classpath:/mapper/*.xml
  type-aliases-package: com.example.entity
  configuration:
    map-underscore-to-camel-case: true

logging:
  level:
    com.baomidou.mybatisplus: debug
    org.mybatis: debug
```

### 启动类配置

```java
@EnableAspectJAutoProxy
@SpringBootApplication(scanBasePackages = "com.example.**")
@MapperScan("com.example.dao.**")
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```
