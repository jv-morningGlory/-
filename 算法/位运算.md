# 位运算

---

## 补码基础：-1 的二进制表示

计算机用**补码**表示负数，以 8 位为例：

| 步骤 | 计算 | 二进制 |
|------|------|--------|
| ① 绝对值 | +1 | `0000 0001` |
| ② 取反（反码） | ~1 | `1111 1110` |
| ③ 加 1（补码） | 反码 + 1 | `1111 1111` |

所以 **-1 的 8 位补码 = `1111 1111`**

不同位宽下的表示：

| 位宽 | -1 的二进制 |
|------|------------|
| 8 位 | `1111 1111` |
| 16 位 | `1111 1111 1111 1111` |
| 32 位（int） | `1111 1111 1111 1111 1111 1111 1111 1111` |
| 64 位（long） | 全部是 1，共 64 个 1 |

> **核心规律：-1 的补码在任意位宽下，所有位全为 1。**

```java
~0  == -1                        // 0 取反得到全 1，就是 -1
-1 >>> 1 == Integer.MAX_VALUE    // 32 个 1 无符号右移 1 位 = 0111...111
```

## &（按位与）

按位与运算是对两个数的每一位进行比较，只有在对应的两位**都为 1** 时，结果才为 1；否则，结果为 0。

```
数字A = 5      （101）
数字B = 3      （011）

A & B：
  1 0 1
& 0 1 1
-------
  0 0 1    → 结果为 1
```

### 简单案例：判断奇偶

```java
// 最低位为 1 → 奇数，为 0 → 偶数
boolean isOdd = (n & 1) == 1;

// 推演：
//   5 = 101  →  101 & 001 = 1  ✅ 奇数
//   6 = 110  →  110 & 001 = 0  ✅ 偶数
```

> 比 `n % 2 != 0` 更快，因为位运算直接看最低位。

### 简单案例：判断 2 的幂

```java
// 2 的幂的二进制只有一个 1，如 4=100, 8=1000
// n & (n-1) 会把最低位的 1 清零，结果为 0 就是 2 的幂
boolean isPowerOfTwo = n > 0 && (n & (n - 1)) == 0;

// 推演：
//   n=8   = 1000,  n-1=7=0111  →  1000 & 0111 = 0  ✅ 是 2 的幂
//   n=6   = 0110,  n-1=5=0101  →  0110 & 0101 = 4  ✅ 不是
```

### 简单案例：权限校验

```java
int SELECT = 1 << 0;   // 0001
int INSERT = 1 << 1;   // 0010
int UPDATE = 1 << 2;   // 0100
int DELETE = 1 << 3;   // 1000

int userPermission = SELECT | INSERT | UPDATE;  // 0111

// 检查是否有 UPDATE 权限
boolean canUpdate = (userPermission & UPDATE) != 0;   // 0111 & 0100 = 0100 ≠ 0 → true

// 检查是否有 DELETE 权限
boolean canDelete = (userPermission & DELETE) != 0;   // 0111 & 1000 = 0000 = 0 → false

// 推演（检查 UPDATE）：
//   0111  (用户权限)
// & 0100  (UPDATE)
// -------
//   0100  ≠ 0 → 有该权限 ✅
```

### 实际应用：固定位数计数器（满归零）

利用 `& 掩码` 可以实现一个**固定位数的计数器**，到达上限后自动归零，比取模 `%` 效率更高。

以 Snowflake（雪花算法）中的序列号为例，12 位序列号最大值为 4095：

```java
// 序列掩码：低 12 位全为 1，高位全为 0
long SEQUENCE_MASK = ~(-1L << 12);  // = 4095 = 0b111111111111

// 自增 + 满归零
long sequence = (this.sequence + 1) & SEQUENCE_MASK;
```

**原理推演：**

```
SEQUENCE_MASK = 0b 0000 0000 0000 0000 0000 0000 0000 0000 0000 0000 0000 0000 0000 0000 1111 1111 1111

sequence = 4094 时：
  4094 + 1 = 4095 = 0b 111111111111
  4095 & MASK = 0b 111111111111 & 0b 111111111111 = 4095  ✅ 正常

sequence = 4095 时（已满）：
  4095 + 1 = 4096 = 0b 1 000000000000   （第 13 位变为 1）
  4096 & MASK = 0b 1 000000000000
                & 0b 0 111111111111
                = 0b 0 000000000000 = 0   ✅ 自动归零！
```

> **本质：掩码的高位全为 0，所以任何超出固定位数的进位都会被 `&` 清除，实现自动归零。** 等价于 `(n + 1) % 4096`，但位运算更快。

## |（按位或）

按位或运算是对两个数的每一位进行比较，对应的两位**有一位是 1**，结果就为 1。

```
数字A = 5      （101）
数字B = 3      （011）

A | B：
  1 0 1
| 0 1 1
-------
  1 1 1    → 结果为 7
```

### 实际应用：拼接多个字段为一个 ID（Snowflake）

Snowflake 雪花算法中，将时间戳、数据中心 ID、机器 ID、序列号**拼接到同一个 long** 中，用的就是 `|`：

```java
// 各部分先左移到对应位置，再用 | 拼合
return ((timestamp - twepoch) << TIMESTAMP_LEFT_SHIFT)   // 时间戳占高 41 位
        | (dataCenterId << DATA_CENTER_ID_SHIFT)          // 数据中心占中间 5 位
        | (workerId << WORKER_ID_SHIFT)                   // 机器 ID 占中间 5 位
        | sequence;                                       // 序列号占低 12 位
```

**原理：各部分左移后，彼此占据不同的位段，互不重叠，用 `|` 即可合并。**

```
时间戳左移22位：  [41bit 时间戳] [22个0]
数据中心左移17位：               [5bit] [17个0]
机器ID左移12位：                        [5bit] [12个0]
序列号：                                      [12bit]

按位或拼接结果： [41bit时间戳][5bit数据中心][5bit机器ID][12bit序列号]
```

> **前提：各部分占用的位段不能重叠。** 只要每个字段在自己的位段内，`|` 就相当于"拼接"，因为 `0 | x = x`。

## ^（按位异或）

对两个操作数的每一位进行异或操作，两个位**不同时结果为 1**，**相同时为 0**。

```
数字A = 5      （101）
数字B = 3      （011）

A ^ B：
  1 0 1
^ 0 1 1
-------
  1 1 0    → 结果为 6
```

### 实际应用：计算固定位数的最大值（Snowflake）

Snowflake 中用 `^` 配合 `-1` 来计算某个位宽能表示的最大值：

```java
// 5 位 workerId 的最大值
long MAX_WORKER_ID = -1L ^ (-1L << 5);  // = 31 = 0b11111

// 12 位序列号的最大值
long SEQUENCE_MASK = -1L ^ (-1L << 12); // = 4095 = 0b111111111111
```

**原理推演（以 5 位为例）：**

```
-1L       = 1111 1111 1111 ... 1111 1111  （全 1）
-1L << 5  = 1111 1111 1111 ... 1110 0000  （低 5 位变 0）

-1L ^ (-1L << 5)：
  1111 ... 1111 1111
^ 1111 ... 1110 0000
-------------------
  0000 ... 0001 1111  = 31  ✅ 低 5 位全为 1，即 5 位最大值
```

> **本质：`-1` 是全 1，`-1 << n` 把低 n 位清零，`-1 ^ (-1 << n)` 让低 n 位恢复为 1、高位变为 0。** 等价于 `~(-1L << n)`，两种写法效果相同。

## >>>（无符号右移）

将操作数的二进制表示向右移动指定位数，**左侧空位补 0**。

```java
A      = 0000 0001  0000 0010
A >>> 8 = 0000 0000  0000 0001
```

### 实际应用：字节拆分（从 int 中取高/低字节）

```java
// int 拆成两个 short（高 16 位 和 低 16 位）
int value = 0x00010002;

int high = value >>> 16;   // 0x00000001
int low  = value & 0xFFFF; // 0x00000002
```

> **`>>>` 与 `>>` 的区别在负数上才体现**：`>>` 补符号位（负数补 1），`>>>` 一律补 0。处理无符号数据（如网络字节、哈希值）时用 `>>>` 避免符号位污染。

---

## >>（带符号右移）

保留符号位（最高位），右侧移出的位丢弃，**左侧空位用符号位填充**。

```java
// 正数示例 (42 >> 2)
00101010 (42)
>> 2
--------
00001010 (10)   // 左侧补 0

// 负数示例 (-42 >> 2)
11010110 (-42 的补码)
>> 2
--------
11110101 (-11 的补码)   // 左侧补 1，仍是负数
```

### 实际应用：从 Snowflake ID 中反解字段

Snowflake 生成 ID 后，可以用 `>>` + `&` 反推出各字段：

```java
// 从 ID 中提取 workerId
public long getWorkerId(long id) {
    return id >> WORKER_ID_SHIFT & ~(-1L << WORKER_ID_BITS);
}

// 从 ID 中提取数据中心 ID
public long getDataCenterId(long id) {
    return id >> DATA_CENTER_ID_SHIFT & ~(-1L << DATA_CENTER_ID_BITS);
}

// 从 ID 中提取生成时间
public long getGenerateDateTime(long id) {
    return (id >> TIMESTAMP_LEFT_SHIFT & ~(-1L << 41L)) + twepoch;
}
```

**原理（以提取 workerId 为例）：**

```
原始 ID：[41bit时间戳][5bit数据中心][5bit机器ID][12bit序列号]

① id >> 12：右移 12 位，把序列号移掉
   → [22个0][41bit时间戳][5bit数据中心][5bit机器ID]

② & ~(-1L << 5)：用掩码只保留低 5 位
   → [59个0][5bit机器ID]  ✅
```

> **套路：`>> n` 甩掉右侧不需要的位，`& mask` 截取左侧需要的固定位数。** 这就是 `>>` 和 `&` 的经典组合。

## <<（左移）

将操作数的二进制表示向左移动指定位数，**右侧补 0**，等同于乘以 2 的 n 次方。

```java
A      = 0000 0010   (2)
A << 3 = 0001 0000   (16)  // 2 × 2³ = 16
```

### 实际应用：为各字段预留位段（Snowflake）

Snowflake 中用 `<<` 计算每个字段的左移位数，将字段放到正确位置：

```java
long SEQUENCE_BITS = 12L;
long WORKER_ID_BITS = 5L;
long DATA_CENTER_ID_BITS = 5L;

// 机器节点左移 12 位（跳过序列号的 12 位）
long WORKER_ID_SHIFT = SEQUENCE_BITS;                              // 12

// 数据中心左移 17 位（跳过序列号 12 位 + 机器 ID 5 位）
long DATA_CENTER_ID_SHIFT = SEQUENCE_BITS + WORKER_ID_BITS;        // 17

// 时间戳左移 22 位（跳过序列号 12 + 机器 5 + 数据中心 5）
long TIMESTAMP_LEFT_SHIFT = SEQUENCE_BITS + WORKER_ID_BITS + DATA_CENTER_ID_BITS; // 22
```

> **本质：`<< n` 就是把数据向左挪 n 个坑位，给右边的字段腾出空间。** 配合 `|` 就能将多个字段拼接到一个整数中。

## ~（取反）

对操作数的每一位取反，**0 变 1，1 变 0**（一元运算符）。

```
A   = 0000 1100
~A  = 1111 0011
```

### 实际应用：生成固定位数的掩码（Snowflake）

Snowflake 中用 `~` 配合 `<<` 来生成指定位数的掩码：

```java
// 序列掩码：低 12 位全为 1，高位全为 0
long SEQUENCE_MASK = ~(-1L << 12);  // = 4095

// workerId 掩码：低 5 位全为 1，高位全为 0
long WORKER_ID_MASK = ~(-1L << 5);  // = 31
```

**原理推演（以 12 位为例）：**

```
-1L       = 1111 1111 1111 ... 1111 1111  （64 位全 1）
-1L << 12 = 1111 1111 1111 ... 1111 0000 0000 0000  （低 12 位变 0）

~(-1L << 12)：
  先左移：... 1111 0000 0000 0000
  再取反：... 0000 1111 1111 1111  = 4095  ✅
```

> **生成 n 位掩码的万能公式：`~(-1L << n)`。** 先把全 1 左移 n 位（低 n 位清零），再取反（低 n 位变回 1，高位清零）。

## 业务实战案例

掌握了雪花算法中的位运算技巧后，这些手法在业务中还有很多应用场景。

### 权限管理（RBAC）

用一个 `int` 的每一位代表一种权限，32 位可以表示 32 种权限：

```java
// 定义权限
int SELECT = 1 << 0;   // 0001
int INSERT = 1 << 1;   // 0010
int UPDATE = 1 << 2;   // 0100
int DELETE = 1 << 3;   // 1000

// 授予多个权限（| 拼接）
int permission = SELECT | INSERT | UPDATE;   // 0111 = 7

// 判断是否有某权限（& 检查）
boolean canUpdate = (permission & UPDATE) != 0;   // true
boolean canDelete = (permission & DELETE) != 0;   // false

// 移除权限（& ~ 清除）
permission = permission & ~INSERT;   // 0111 & ~0010 = 0101 = 5

// 切换权限（^ 翻转：有则移除，无则添加）
permission = permission ^ UPDATE;    // 0101 ^ 0100 = 0001
```

> **和雪花算法的关系**：雪花用 `|` 拼接字段，权限用 `|` 拼接权限——本质一样，都是每个字段占不同的位。

### 用户标签 / 特征标记

一个字段存多个布尔标记，省字段、省索引：

```java
// 定义标签
long VIP         = 1L << 0;   // 是否 VIP
long REAL_NAME   = 1L << 1;   // 是否实名
long BIND_PHONE  = 1L << 2;   // 是否绑手机
long BIND_EMAIL  = 1L << 3;   // 是否绑邮箱
long RISK_USER   = 1L << 4;   // 是否风控用户

// 用户注册：实名 + 绑手机
long userFlag = REAL_NAME | BIND_PHONE;   // 0110 = 6

// 开通 VIP（|= 设置第 N 位为 1）
userFlag |= VIP;   // 0111 = 7

// 判断是否 VIP
boolean isVip = (userFlag & VIP) != 0;   // true

// 标记为风控用户
userFlag |= RISK_USER;   // 10111 = 23

// 查询：VIP 且已实名的用户
// SQL: WHERE user_flag & 3 = 3   （3 = VIP | REAL_NAME）
```

> 数据库存一个 `BIGINT` 就能表示 64 种标记，比建 64 个 `TINYINT` 列高效得多。

### Redis Bitmap — 签到 / 活跃统计

Redis 的 `SETBIT`/`GETBIT` 本质就是位操作，用极小的内存做统计：

```bash
# 用户 1001 在第 5 天签到（setbit 第 5 位为 1）
SETBIT sign:1001:202606 5 1

# 检查第 5 天是否签到
GETBIT sign:1001:202606 5    # → 1

# 统计本月签到天数（统计所有 1 的个数）
BITCOUNT sign:1001:202606     # → 15

# 连续签到检查：用 BITOP AND 对比两天的数据
BITOP AND result sign:1001:202606 sign:1001:202605
```

> **1 亿用户 × 365 天的签到数据只需约 4.3 GB**，比关系数据库省几十倍。

### 布隆过滤器 — 防缓存穿透

用位数组 + 多次哈希判断元素**可能存在**或**一定不存在**：

```java
// Guava BloomFilter 底层就是位操作
BloomFilter<Long> userIdFilter = BloomFilter.create(
    Funnels.longFunnel(), 1_000_000, 0.01   // 100 万元素，1% 误判率
);

// 查询前先判断
if (!userIdFilter.mightContain(userId)) {
    return null;   // 一定不存在，直接返回，不打数据库
}
// 可能存在，再查数据库
```

> 底层每次 `put` 就是对多个位做 `|`（置 1），`mightContain` 就是对多个位做 `&`（全为 1 才可能存在）。

### RGB 颜色值操作

一个 `int` 存 RGB 三个通道，用位运算拆分和合并：

```java
// 打包：RGB → int（| 拼接，和雪花算法一样）
int color = (255 << 16) | (128 << 8) | 64;   // R=255, G=128, B=64

// 拆包：int → R/G/B（>> + & 反解，和雪花反解字段一样）
int r = (color >> 16) & 0xFF;   // 255
int g = (color >> 8)  & 0xFF;   // 128
int b =  color        & 0xFF;   // 64
```

## 核心套路总结

| 套路 | 操作 | 业务场景 |
|------|------|---------|
| 多字段拼接到一个整数 | `\|` | 雪花算法 ID、RGB 颜色、权限组合 |
| 从一个整数中提取字段 | `>>` + `&` | 反解 ID、拆颜色通道、读权限 |
| 固定位数计数器满归零 | `& mask` | 雪花序列号、环形缓冲区 |
| 生成 N 位掩码 | `~(-1 << N)` | 截取固定位、权限掩码 |
| 判断第 N 位是否为 1 | `& (1 << N)` | 权限校验、标签判断 |
| 设置第 N 位为 1 | `\|= (1 << N)` | 授权、打标签、签到 |
| 清除第 N 位 | `&= ~(1 << N)` | 撤销权限、移除标签 |

> **一句话：只要你想把多个小值塞进一个大值，或者用一个整数表示多个开关，位运算就是最优解。**
