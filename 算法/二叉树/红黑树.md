# 红黑树

> 图例：`20黑` = 黑色节点（计入黑高的骨架），`10红` = 红色节点（不计入黑高的额外一层）。空指针 `NIL` 一律当成黑叶子，不画时默认存在。

---

## 一、它长什么样

**红黑树**也是 BST：左小右大，中序有序。每个节点多涂一笔颜色，不是红就是黑。

下面这棵是合法红黑树（也是合法 BST，中序 `4 8 12 16 20 24 28`）：

```text
              16黑
            /        \
         8红          24红
        /    \        /    \
     4黑    12黑   20黑    28黑
```

和 AVL 干同一件事：防止 BST 退化成链表。差别是**不看 bf**，看颜色规则。规则比 AVL 松，插入/删除少旋几次。

### 红和黑分别代表什么

**不代表**数值大小、左右、好坏。每个节点多存的 **1 bit 标记**，专门用来维持「大致平衡」。

| 颜色 | 角色 | 计入黑高？ |
| --- | --- | --- |
| **黑** | 骨架。从根到叶子，黑节点个数必须相同 | 计 |
| **红** | 夹在黑骨架缝里的「额外一层」，允许局部先长高，先不旋转 | 不计 |

同一棵树，数黑高时把红当成透明的（路过但不计数）：

```text
              16黑
            /        \
         8红          24红          ← 红，路过不算
        /    \        /    \
     4黑    12黑   20黑    28黑      ← 黑，计数

16黑 → 8红 → 4黑 → NIL     只数黑：16、4、NIL      → 3
16黑 → 8红 → 12黑 → NIL    只数黑：16、12、NIL     → 3
16黑 → 24红 → 20黑 → NIL   只数黑：16、20、NIL     → 3
16黑 → 24红 → 28黑 → NIL   只数黑：16、28、NIL     → 3

四条路黑高都是 3。8红、24红让树「胖」了一层，但黑骨架高度没变。
```

对应到操作：

- **新节点一律涂红**：不增加黑高，第 5 条（每条路黑一样多）暂时不破；最多破「红不连红」
- **根必须黑**：根一定算进每一条路的黑高
- **红不能挨红**：红是「白送的一层」，连着两层红，最长路径就会超过最短的 2 倍，平衡保不住
- **变色 / 旋转**：红变黑 = 把额外一层收进骨架（黑高 +1）；黑变红 = 从骨架里拿出来。旋转只是把红挪到合法位置，手法和 AVL 一样

> AVL 用高度差当平衡信息；红黑树用这 1 bit 颜色当平衡信息。看到红/黑，想的是「算不算进黑高」，不是「这个值是什么」。

同一组数 `10, 20, 30` 三种树的差别：

```text
普通 BST（歪成链）     AVL（左右高度差≤1）     红黑树（允许略歪）

10                      20黑                    20黑
  \                    /    \                   /    \
  20                 10     30               10红    30红
    \
    30
```

AVL 和红黑树这组看起来一样，因为节点少。节点一多，红黑树允许一边暂时更高，换旋转更少。Java 的 `TreeMap` / `TreeSet`、`HashMap` 链表树化，用的都是红黑树。

## 二、五条规则：对的图 / 错的图

合法红黑树必须五条同时成立。逐条看图。

### 规则 1、2：节点非红即黑，根必须是黑

```text
对                          错：根是红

    16黑                        16红   ← 根不能红
   /    \                      /    \
 8红    24红                 8黑    24黑
```

新插入的节点默认涂红（尽量不增加黑高）。如果它变成了根，必须改成黑。

### 规则 3：NIL 空叶子算黑

画完整时，每个空指针都是黑叶子：

```text
          16黑
         /    \
       8红     24红
      /  \     /  \
    NIL  NIL NIL  NIL     ← 这些全是黑
```

平时可以不画 NIL，但数「到叶子的黑节点个数」时，必须把它们算进去。

### 规则 4：红的下面不能再接红（不能红红相邻）

```text
对：红的孩子都是黑              错：红红挨着

        16黑                      16黑
       /    \                    /
     8红    24红               8红
     /  \                     /
   4黑  12黑                4红   ← 8红下面又挂红，违规
```

看到红节点，立刻看它的父、左、右：三个里再出现红，就要修。

### 规则 5：任意节点到下面每个叶子，路上的黑节点个数相同（黑高）

对下面这棵，从根走到每个 NIL，路上有几个黑：

```text
              16黑
            /        \
         8红          24红
        /    \        /    \
     4黑    12黑   20黑    28黑
     / \     / \    / \     / \
   NIL NIL NIL NIL NIL NIL NIL NIL
```

| 路径 | 路上的黑节点 | 黑高 |
| --- | --- | --- |
| 16黑 → 8红 → 4黑 → NIL | 16、4、NIL | 3 |
| 16黑 → 8红 → 12黑 → NIL | 16、12、NIL | 3 |
| 16黑 → 24红 → 20黑 → NIL | 16、20、NIL | 3 |
| 16黑 → 24红 → 28黑 → NIL | 16、28、NIL | 3 |

四条路黑高都是 3，合法。

再看一条违规：

```text
        16黑
       /    \
     8黑    24黑
    /             \
  4黑             NIL

路径 16黑→8黑→4黑→NIL ：黑节点 4 个
路径 16黑→24黑→NIL     ：黑节点 3 个   ← 黑高不一致，违规
```

> 口诀：**根黑、叶黑、红不连红、每条路黑一样多。** 前三条好查，第 5 条从某个节点往下，左右两条路数黑节点，数不一样就是这棵子树坏了。

## 三、为什么不会变成链表（用图看）

黑高相同 + 不能红红相邻，合在一起限制了树高。

黑高 = 3 时，最短和最长长这样：

```text
最短：一路全黑（3 个黑）          最长：红黑相间（3 个黑 + 红夹在中间）

      黑                              黑
     /                               /
   黑                              红
   /                               /
  黑                             黑
  /                              /
 NIL                           红
                               /
                             黑
                             /
                           NIL
```

- 最短路径：只有黑，长度 = 黑高
- 最长路径：每两个黑之间最多夹一个红，长度 < **2 × 黑高**

所以再歪也是「最多高一倍」，不会出现 BST 那种一根筋链表。查找仍是 O(log n)。AVL 卡的是「左右只差 1」，这棵树更矮；红黑树卡的是「最长不超过最短的 2 倍」，略高，但旋转更少。

## 四、插入后怎么修（对着图做）

新节点一律先涂 **红**，按 BST 规则挂上去。只可能违反「红红相邻」。看**叔叔**（父节点的兄弟）决定怎么修。

下面三种都是：刚插了 `N红`，它的父 `P` 也是红，祖父 `G` 是黑。

### 情况 1：叔叔是红 → 只变色，不旋转

```text
插入前（叔叔 U 是红）              变色后

        G黑                            G红     ← 祖父变红，可能还要往上查
       /   \                          /   \
     P红   U红                      P黑   U黑
     /                              /
   N红                            N红
```

动作：父、叔改黑，祖父改红。红红相邻消失。若祖父的父也是红，把祖父当成新的 N，继续往上。

### 情况 2：叔叔是黑，且拐弯（LR / RL）→ 先旋成一条线

左拐右（LR），和 AVL 的 LR 第一下一样：先对父节点左旋。

```text
        G黑                          G黑
       /                            /
     P红            →             N红      ← 先转成「一条线」（情况 3）
       \                          /
       N红                      P红
```

右拐左（RL）则先对父节点右旋。转完后按情况 3 再处理。

### 情况 3：叔叔是黑，且同向（LL / RR）→ 旋祖父 + 变色

LL（新节点在祖父的左-左），对祖父右旋，和 AVL 的 LL 同一手：

```text
        G黑                          P黑
       /                            /   \
     P红            →             N红   G红
     /
   N红
```

动作：对 G 右旋；P 改黑、G 改红。RR 则对 G 左旋，镜像。

> 旋转手法和 AVL 完全一样（左旋/右旋，内侧子树过继）。差别只是**触发条件**：AVL 看 bf=±2，红黑树看「红红相邻」。

三种情况对照：

| 叔叔颜色 | 新节点相对祖父 | 做法 |
| --- | --- | --- |
| 红 | 不管 | 父叔变黑、祖父变红，再往上 |
| 黑 | 拐弯（LR / RL） | 先对父旋一次，变成下面一行 |
| 黑 | 同向（LL / RR） | 对祖父旋一次，父黑祖父红 |

## 五、插一遍最小例子（10 → 20 → 30）

对应 AVL 笔记里那组数，看红黑树怎么走。

**插 10：** 空树，新节点本该红，但根必须黑。

```text
10黑
```

**插 20：** BST 挂右边，新节点涂红。父是黑，不红红相邻，结束。

```text
10黑
  \
  20红
```

**插 30：** 挂在 20 右边，涂红 → 20红 下面又是 30红，违规。

```text
10黑                    10黑                      20黑
  \                       \                      /    \
  20红         →          30红        →        10红    30红
    \                     /
    30红                20红
```

1. 叔叔是 NIL（黑），且是 RR 同向 → 走情况 3
2. 对 10 左旋，20 改黑、10 改红

最终根是 20，和 AVL 插完这组的形状一样。中序仍是 `10 20 30`。

## 六、看到之后该做什么

| 你看到的 | 判断 | 动作 |
| --- | --- | --- |
| `TreeMap` / `TreeSet` | 底层就是红黑树 | 有序、get/put 都是 O(log n) |
| `HashMap` 某个桶树化 | 链表太长，防哈希碰撞退化 | 不用自己实现 |
| 题目要手写平衡树 | 考试常见 AVL | 红黑树记五条规则 + 三种插入修法即可 |
| 给一棵树问是否红黑树 | 先确认 BST，再查五条 | 根黑、无红红、每条路黑高相同 |

和 AVL 怎么选：

| | AVL | 红黑树 |
| --- | --- | --- |
| 平衡 | 左右高度差 ≤ 1，更矮 | 最长 < 2 × 最短，略高 |
| 插入/删除 | 旋转多 | 经常只变色 |
| Java 里 | 基本不用 | `TreeMap` / `TreeSet` / `HashMap` 树化 |
