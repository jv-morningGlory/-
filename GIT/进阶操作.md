# Git 进阶操作：Stash / Rebase / Reset / Revert

---

## 1. Stash（暂存）

将工作区和暂存区的改动保存到 Git 栈中，清理工作目录。

> **注意**：stash 只管理已跟踪文件，`Untracked files` 不受 stash 控制，这部分代码很容易丢失。

### 1.1 命令

```bash
git stash                    # 入栈（保存当前改动）
git stash push -m "注释"     # 入栈并添加说明

git stash pop                # 出栈（恢复最近一次 stash 并从栈中删除）
git stash apply              # 预览式出栈（恢复但不删除）
git stash list               # 查看所有 stash 记录
git stash show <index>       # 查看某次 stash 的文件变动
git stash drop               # 删除最近一次 stash
git stash clear              # 清空全部 stash
```

> `list` 只列记录摘要，`show` 显示具体文件改动。

### 1.2 场景一：提交前先同步远程

```bash
git add --all
git stash              # 暂存当前修改
git pull               # 拉取最新代码
git stash pop          # 恢复自己的修改
# 如有冲突，此时手动解决（避免产生多余 merge commit）
git commit -m "..."
git push
```

### 1.3 场景二：临时切换分支

```bash
# 当前分支 A，紧急处理分支 B 的 bug
git stash
git checkout B
# 处理完 B ...
git checkout A
git stash pop           # 继续 A 的开发
```

## 2. Rebase（变基）

### 2.1 merge vs rebase

| | `git merge` | `git rebase` |
|---|------------|-------------|
| **历史** | 保留分支结构，产生 merge commit | 线性历史，更整洁 |
| **冲突** | 一次性解决 | 逐个 commit 解决 |
| **适用** | 公共分支合并 | 整理个人分支 |

```
merge:   main: A--B--C--M
               \  /
        feature: D--E

rebase:  main: A--B--C--D'--E'
```

### 2.2 合并多次提交

```bash
git rebase -i HEAD~3       # 交互式合并最近 3 次提交
# 将后 2 个标记为 squash，合入第 1 个
```

### 2.3 注意事项

- 不要对**已推送的公共分支**进行 rebase
- rebase 后需要 `git push --force`（仅限个人分支）

## 3. Reset 与 Revert

### 3.1 核心区别

| | `git reset` | `git revert` |
|---|------------|-------------|
| **作用范围** | 本地仓库 | 本地 + 远程 |
| **原理** | 移动 HEAD 指针 | 创建新的反向提交 |
| **是否改写历史** | 是 | 否 |
| **适用** | 撤销未推送的提交 | 撤销已推送的提交 |

### 3.2 Reset 三种模式

```bash
git reset HEAD~             # --mixed(默认)：撤销commit，改动回工作区
git reset HEAD~ --soft      # 撤销commit，改动保留在暂存区
git reset HEAD~ --hard      # 完全回退，所有改动丢失
git reset --hard <hash>     # 回退到指定版本
```

### 3.3 Revert

```bash
git revert <commit-hash>    # 撤销某次提交，生成一个新的"反向"提交
```

> **原则**：已推送的提交必须用 `revert`，未推送的用 `reset`。

## 4. 常见操作速查

```bash
# 取消暂存
git reset HEAD <file>

# 检出历史版本的文件
git checkout <commit-hash> -- <file>

# 删除远程分支
git push origin --delete feature/xxx

# 查看某个文件的修改历史
git log -p <file>

# 查看谁改过某行代码
git blame <file>
```
